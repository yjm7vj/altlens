### Metric Calculation Implementation

Implemented a `CashFlow` dataclass to represent fund cash-flow events:

- `event_date`
- `amount_usd`
- `flow_type`

Implemented `calculate_moic`, which computes:

```text
total distributions / total paid-in capital
```

Capital calls are treated as invested capital. Distributions are treated as returned capital. If there is no invested capital, the function returns `0.0`.

Implemented `calculate_irr`, using XIRR-style logic for irregular real-world fund cash-flow dates.

The IRR calculation:

1. sorts cash flows chronologically
2. converts event dates into year fractions from the first cash-flow date
3. checks that cash flows include both negative and positive values
4. solves for the discount rate that makes net present value equal zero
5. returns `0.0` when a valid IRR cannot be solved

The implementation uses SciPy's `brentq` root solver. This follows the build plan's recommendation to use a proven numerical method instead of relying on a fragile custom Newton-method implementation.

### Tests Added

### Development Challenges

#### Dependency Setup

The first test run failed because `pytest` was not installed in the local Python environment. Installing all development dependencies at once took longer than expected because scientific Python packages were involved. Installing `pytest` separately after SciPy was available resolved the immediate test blocker.

This matters for future development because setup should stay simple and documented. If dependency installation becomes slow or unreliable, the project may need pinned versions or a more explicit virtual-environment workflow.

#### IRR Test Calibration

One multiple-capital-call IRR test initially used an incorrect expected value. The solver returned approximately 15.34%, while the first estimate expected approximately 17.5%.

After reviewing the cash-flow timing, the solver result was correct for:

- `-100` on 2020-01-01
- `-50` on 2021-01-01
- `+220` on 2023-01-01

The expected value was corrected to approximately 15.3%.

This is an important development lesson for AltLens: IRR is sensitive to timing, and intuitive estimates can be misleading. Metric tests should continue to use independently checked examples whenever new financial calculations are added.
